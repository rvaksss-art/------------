# Функциональность создания заявки на обмен валюты

Версия: 0.1
Статус: черновик для согласования

## 1. Назначение

Функциональность предназначена для моментального обмена валют между счетами внутреннего кошелька пользователя, например RUB → USDT.

Пользователь должен иметь возможность:

* выбрать валютную пару;
* увидеть доступные балансы;
* получить актуальный курс;
* указать сумму списания;
* увидеть рассчитанную сумму получения;
* проверить параметры операции;
* подтвердить обмен;
* получить результат выполнения заявки.

## 2. Границы функциональности

### В рамках задачи

* отображение балансов пользователя;
* выбор валютной пары;
* получение актуального курса;
* расчёт суммы получения;
* проверка достаточности средств;
* создание и выполнение заявки;
* обработка изменения курса;
* отображение результата операции;
* предотвращение повторного создания одной заявки.

### Вне рамок задачи

* регистрация и авторизация пользователя;
* KYC/AML-проверки;
* пополнение и вывод денежных средств;
* покупка валюты с банковской карты;
* история всех операций кошелька;
* управление справочником валют;
* ручное администрирование курсов;
* отмена уже исполненного обмена.

## 3. Допущения

1. Пользователь авторизован.
2. У пользователя уже создан внутренний кошелёк.
3. Для каждой валюты используется отдельный баланс.
4. Валютная пара RUB/USDT доступна для обмена.
5. Обмен производится только между счетами одного пользователя.
6. Пользователь вводит сумму в валюте списания.
7. Сумма получения рассчитывается автоматически.
8. Полученный курс действует ограниченное время — предварительно 30 секунд.
9. Комиссия может зависеть от валютной пары и включается в расчёт.
10. При изменении или истечении курса требуется повторное подтверждение.
11. После подтверждения система создаёт заявку и пытается выполнить её автоматически.
12. Реальное списание и зачисление должны выполняться как единая операция: либо выполняются оба действия, либо не выполняется ни одно.

# 7. Статусы заявки

| Статус       | Описание                                          |
| ------------ | ------------------------------------------------- |
| `CREATED`    | Заявка создана и зарегистрирована системой.       |
| `PROCESSING` | Выполняется списание и зачисление средств.        |
| `COMPLETED`  | Обмен успешно выполнен.                           |
| `REJECTED`   | Заявка отклонена из-за бизнес-ограничения.        |
| `FAILED`     | Выполнение не завершено из-за технической ошибки. |

Черновик формы на экране до отправки не считается заявкой и не получает отдельного серверного статуса.

# 9. User Story

## US-01. Обмен валюты

Как авторизованный пользователь внутреннего кошелька,
я хочу выбрать валютную пару, указать сумму и заранее увидеть условия обмена,
чтобы подтвердить и выполнить обмен по понятному и актуальному курсу.

### Критерии приёмки

1. Пользователь видит доступные балансы.
2. Пользователь может выбрать разные валюты списания и получения.
3. После ввода суммы система показывает сумму получения, курс и комиссию.
4. Система не позволяет подтвердить обмен при недостаточном балансе.
5. Система не позволяет использовать истёкший курс.
6. При изменении курса система показывает новые условия и запрашивает повторное подтверждение.
7. После успешного обмена пользователь получает номер заявки и обновлённые балансы.
8. Повторная отправка одного запроса не приводит к повторному списанию.

# 10. Use Case

## UC-01. Создание и выполнение заявки на обмен валюты

**Основной актор:** пользователь.
**Цель:** обменять одну валюту внутреннего кошелька на другую.
**Триггер:** пользователь открывает раздел «Обмен валют».

### Предусловия

1. Пользователь авторизован.
2. Кошелёк пользователя активен.
3. Валютная пара доступна.
4. Сервис получения курса работает.
5. Пользователь имеет положительный баланс валюты списания.

### Happy Path

1. Пользователь открывает экран обмена.
2. Система загружает доступные валютные пары и балансы.
3. Система устанавливает пару RUB → USDT.
4. Система показывает текущий курс.
5. Пользователь вводит сумму RUB.
6. Система проверяет формат, лимиты и доступный баланс.
7. Система получает котировку и рассчитывает сумму USDT.
8. Система показывает курс, комиссию, сумму списания и сумму получения.
9. Пользователь нажимает «Обменять».
10. Система проверяет актуальность котировки и доступный баланс.
11. Система создаёт заявку с уникальным номером.
12. Система списывает RUB и зачисляет USDT.
13. Система переводит заявку в статус `COMPLETED`.
14. Система показывает результат обмена.
15. Система обновляет балансы пользователя.

### Результат

* заявка сохранена;
* средства в исходной валюте списаны;
* средства в целевой валюте зачислены;
* пользователь получил подтверждение операции;
* повторная отправка того же запроса не создаст второй обмен.

# 11. Альтернативные и негативные сценарии

## AS-01. Недостаточно средств

Точка отклонения: шаг 6 или шаг 10 основного сценария.

1. Система определяет, что сумма списания превышает доступный баланс.
2. Система показывает сообщение «Недостаточно средств».
3. Кнопка «Обменять» блокируется.
4. Заявка не создаётся.
5. Пользователь может уменьшить сумму или изменить валюту.

## AS-02. Курс изменился

Точка отклонения: шаг 10 основного сценария.

1. Система определяет, что котировка истекла или больше не актуальна.
2. Обмен по новому курсу автоматически не выполняется.
3. Система запрашивает новую котировку.
4. Интерфейс показывает старое и новое значение либо выделяет изменившиеся условия.
5. Пользователь получает сообщение «Курс изменился. Проверьте новые условия».
6. Пользователь подтверждает новые условия либо отказывается от операции.
7. Только после повторного подтверждения создаётся заявка.

## AS-03. Некорректная сумма

Точка отклонения: шаг 6 основного сценария.

Возможные причины:

* сумма равна нулю;
* введено отрицательное значение;
* введены недопустимые символы;
* превышена допустимая точность;
* сумма меньше минимального лимита;
* сумма больше максимального лимита.

Результат:

* система показывает конкретную ошибку;
* расчёт не выполняется;
* кнопка подтверждения заблокирована;
* заявка не создаётся.

## AS-04. Валютная пара недоступна

1. Выбранная пара временно недоступна для обмена.
2. Система показывает соответствующее сообщение.
3. Поля расчёта и кнопка подтверждения блокируются.
4. Пользователь может выбрать другую пару.

## AS-05. Баланс изменился перед подтверждением

1. Во время оформления пользователь совершил другую операцию.
2. Перед созданием заявки система повторно проверила баланс.
3. Доступных средств оказалось недостаточно.
4. Заявка не создаётся либо получает статус `REJECTED`.
5. Пользователь видит обновлённый баланс и причину отказа.

## AS-06. Повторное нажатие кнопки

1. Пользователь несколько раз нажимает «Обменять» или повторяет запрос.
2. Система распознаёт одинаковый ключ идемпотентности.
3. Новая заявка и повторное списание не создаются.
4. Пользователю возвращается результат ранее созданной заявки.

## AS-07. Техническая ошибка

1. Во время создания или выполнения заявки возникает техническая ошибка.
2. Система не допускает частичного изменения балансов.
3. Заявка получает статус `FAILED`, если она уже была создана.
4. Пользователь видит сообщение без внутренних технических подробностей.
5. Пользователю предлагается повторить операцию позднее.

## Пример расчёта

Исходные данные:

* баланс: 50 000 RUB;
* сумма обмена: 10 000 RUB;
* курс: 1 USDT = 92,40 RUB;
* комиссия: 50 RUB.

Формула:

`Сумма получения = (Сумма списания − Комиссия) / Курс`

Расчёт:

`(10 000 − 50) / 92,40 = 107,68 USDT`

Пользователь до подтверждения видит:

* будет списано: 10 000 RUB;
* комиссия: 50 RUB;
* будет получено: 107,68 USDT;
* курс: 1 USDT = 92,40 RUB;
* срок действия курса.
